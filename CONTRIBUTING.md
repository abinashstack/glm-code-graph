# Contributing to GLM Code Graph Demo

Thank you for your interest in contributing! This repository is a demonstration project, but your contributions can help make it a valuable resource for the community.

## Code of Conduct

- Be respectful and inclusive
- Ask questions if you're unsure
- Provide constructive feedback
- Focus on making the project better

## How to Contribute

### Reporting Issues

1. Check existing issues first
2. Use the [Question template](.github/ISSUE_TEMPLATE/question.md)
3. Include:
   - Clear description of the issue
   - Steps to reproduce
   - Expected vs actual behavior
   - Screenshots if applicable

### Suggesting Improvements

1. Check existing issues
2. Use the [Question template](.github/ISSUE_TEMPLATE/question.md)
3. Include:
   - Clear description of the feature/fix
   - Why it's needed
   - How it should work

### Pull Requests

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/amazing-feature`
3. Make your changes
4. Commit changes: `git commit -m "Add amazing feature"`
5. Push: `git push origin feature/amazing-feature`
6. Open a Pull Request using the [PR template](.github/PULL_REQUEST_TEMPLATE.md)

### What to Contribute

Great contributions include:

**Documentation:**
- Improve the README
- Add more examples
- Create tutorials
- Translate to other languages

**Code:**
- Add more verification scripts
- Implement blast radius engine
- Add more language support
- Add CI/CD integrations

**Testing:**
- Add unit tests
- Add integration tests
- Improve test coverage

**Examples:**
- Add more example codebases
- Create different scenarios
- Show edge cases

## Development Setup

```bash
# Clone your fork
git clone https://github.com/YOUR_USERNAME/glm-code-graph-demo.git
cd glm-code-graph-demo

# Create feature branch
git checkout -b feature/amazing-feature

# Install dependencies (if needed)
# pip install -r requirements.txt

# Make your changes
# ...

# Test your changes

# Commit and push
git add .
git commit -m "Add amazing feature"
git push origin feature/amazing-feature
```

## Pull Request Checklist

Before submitting your PR, make sure:

- [ ] Code follows the project's style
- [ ] Code is well-commented (where appropriate)
- [ ] Tests pass locally
- [ ] Documentation is updated (if applicable)
- [ ] PR description explains the changes
- [ ] Related issues are mentioned

## Getting Feedback

1. Wait for maintainers to review
2. Address feedback
3. Respond to comments
4. Once approved, your PR will be merged

## Project Guidelines

### For Feature Requests

**Good ideas:**
- Implement new blast radius scenarios
- Add more language support
- Create example projects
- Performance optimizations

**Considerations:**
- Keep it simple and focused
- Maintain backward compatibility
- Consider edge cases
- Add tests

### For Bug Fixes

**Good fixes:**
- Address root cause, not symptoms
- Include tests for the fix
- Update documentation
- Explain the change clearly

### For Documentation

**Good docs:**
- Clear and concise
- Include code examples
- Updated regularly
- Easy to understand
